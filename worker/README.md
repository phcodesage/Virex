# Virex API proxy

A Cloudflare Worker that holds the DeepSeek API key server-side and enforces
plan limits. The macOS app talks to this instead of DeepSeek directly, so the
key never ships inside a binary anyone can inspect.

| Plan | Limit |
|---|---|
| Free | 10 rewrites/day per device |
| Pro | Unlimited |

## Deploy

```bash
cd worker
npx wrangler login                       # one-time, opens a browser

# 1. Create the KV namespace and paste the printed id into wrangler.toml
npx wrangler kv namespace create VIREX_KV

# 2. Store the DeepSeek key as an encrypted secret (never commit it)
npx wrangler secret put DEEPSEEK_API_KEY

# 3. Ship it
npx wrangler deploy
```

Deploy prints your URL, e.g. `https://virex-api.<subdomain>.workers.dev`.
Put that in `src-tauri/src/config.rs` as `API_BASE`, then rebuild the app.

## Endpoints

### `POST /v1/rewrite`
Streams the rewrite back as SSE (a passthrough of DeepSeek's stream).

```
Headers: X-Virex-Device: <uuid>
         Authorization: Bearer <licence>   (optional; Pro)
Body:    { "text": "...", "system": "..." }   // system optional
```

`429` with `{"error":"daily_limit_reached"}` once the free allowance is gone.

### `GET /v1/usage`
What the Settings window shows.

```
Headers: X-Virex-Device: <uuid>
→ { "plan": "free", "used": 3, "limit": 10, "remaining": 7 }
```

## Pro licences (Ko-fi)

Ko-fi takes the payment; this Worker turns it into a licence key. No accounts,
no payment code of our own.

### Wire up the webhook

1. Create a **$10/month membership tier** on Ko-fi.
2. Ko-fi → **Settings → Webhooks**: set the URL to
   `https://virex-api.<subdomain>.workers.dev/webhooks/kofi` and copy the
   **Verification Token**.
3. Store it, plus a token guarding the admin endpoint:

   ```bash
   npx wrangler secret put KOFI_VERIFICATION_TOKEN
   npx wrangler secret put ADMIN_TOKEN
   npx wrangler deploy
   ```

Every payment now hits the Worker. Payments of `PRO_MIN_AMOUNT` or more issue a
key (renewals reuse the same one); smaller amounts are treated as tips and
ignored.

### Getting the key to the customer

**By hand (no setup).** Ko-fi emails you about each payment. Look up the key:

```bash
curl -H "X-Admin-Token: $ADMIN_TOKEN" \
  "https://virex-api.<subdomain>.workers.dev/admin/license?email=buyer@example.com"
```

Then reply to them with it. Fine for the first handful of customers.

**Automatically (configured).** Keys are emailed by [Resend](https://resend.com)
from `Virex <keys@swe-rech.site>` the moment someone subscribes — first payment
and renewals both. `RESEND_API_KEY` is set as a Worker secret;
`LICENSE_FROM_EMAIL` lives in `wrangler.toml`.

To move to a different sender, verify the domain at Resend, update
`LICENSE_FROM_EMAIL`, and redeploy.

### How cancellation works

Licences carry a 35-day TTL that each monthly payment refreshes. Stop paying and
the key simply lapses, so no "subscription cancelled" event is required — Ko-fi
doesn't reliably send one.

### Comping someone

```bash
npx wrangler kv key put --binding VIREX_KV "license:VIREX-FRIEND-01" "active" --remote
```

Revoke by deleting that key (add `--remote`).

> Writes and deletes take up to a minute to take effect — KV caches reads at the
> edge. Measured ~20s in practice. So a revoked key keeps working briefly; that's
> expected, not a bug.

## Cost

Workers' free tier covers 100k requests/day and permits commercial use.
You pay DeepSeek for inference on *all* usage, including free-tier users —
`FREE_DAILY_LIMIT` in `wrangler.toml` is the dial that caps that exposure.

## Abuse notes

Free usage is counted per device id generated by the app. A determined user can
reset it, since the client is open source. That's an accepted trade-off for not
requiring accounts; the daily cap bounds the damage. If abuse shows up, the next
step is requiring a (free) sign-in rather than trusting a device id.
